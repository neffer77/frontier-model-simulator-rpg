# P5.2.12 — Native FrontierOS Knowledge + Code Lab + Artifacts

## Goal
Make the lab's learning and evidence surfaces first-class FrontierOS applications without duplicating the Phase 4B/4C simulation systems that already own organizational knowledge, editable training code, deterministic cluster jobs, and engineering artifacts.

## Native ownership
Three registry applications are command-owned:

- `knowledge.open` → **Knowledge**
- `code-lab.open` → **Code Lab**
- `artifacts.open` → **Artifacts**

Knowledge exposes Lessons, Standards, and Reliability Memory. Code Lab exposes Editor, Jobs, Recovery, and NPC Review. Artifacts exposes Workspace, Metrics, Cluster, and Challenge views.

## Canonical simulation boundary
The existing systems remain mutation owners:

- `knowledge.js` owns organizational knowledge, standards, provenance, confidence, staleness, and reliability effects.
- `code-lab.js` owns editable PyTorch scenarios, deterministic tests, simulated Slurm/Kubernetes jobs, rank failures, checkpoint recovery, and NPC review.
- `engineering-artifacts.js` owns training config edits, deterministic run files, metrics, terminal commands, artifact inspection, and challenge grading.

`command-adapters.js` now provides the native FrontierOS presentation/orchestration boundary. It reads those canonical states, calls their existing mutation functions, and immediately re-renders the native shell. No real cluster or shell command is executed.

## Deep links
Examples:

- `frontieros://knowledge/standards`
- `frontieros://knowledge/reliability`
- `frontieros://code-lab/editor`
- `frontieros://code-lab/recovery`
- `frontieros://artifacts/workspace`
- `frontieros://artifacts/challenge`

## Delivery
The migration deliberately reuses the already-delivered `knowledge.*`, `code-lab.*`, `engineering-artifacts.*`, and `command-adapters.js` assets. Browser, PWA, and Scriptable parity therefore remains intact without introducing duplicate bundles. The PWA cache advances to v48 so existing installations receive the new command-owned behavior.

## Evidence
`tests/knowledge-engineering-frontieros.mjs` runs the three applications through real desktop and phone FrontierOS shells and verifies:

- command-owned application launch
- Knowledge standards deep link
- deterministic Code Lab test correction and distributed job launch
- Code Lab recovery deep link
- Artifacts config mutation through the canonical parser/apply path
- deterministic artifact terminal evidence
- Artifacts challenge deep link
- telemetry for all three native apps
- zero page errors

Focused evidence is written to `artifacts/knowledge-engineering-frontieros` and release-blocked by `frontieros-knowledge-engineering` under release policy v14.
