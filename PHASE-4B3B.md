# Phase 4B.3B — Organizational Knowledge

This phase makes the lab learn from resolved incidents, experiments, and corrective actions.

## Implemented

- Persistent organizational knowledge entries.
- Incident-derived lessons with source incident provenance.
- Experiment-derived lessons when findings are adopted or kept for follow-up.
- Knowledge confidence levels: tentative, supported, strong, institutionalized.
- Confidence increases when the same lesson is reinforced by more sources.
- Model, contributor, and evidence provenance on each knowledge entry.
- Knowledge retrieval during future incidents based on technical domain and incident family.
- Staleness labeling for older lessons.
- Explicit superseded-knowledge state and links to newer lessons.
- Automatic promotion of heavily reinforced lessons into lab standards.
- Corrective-action completion translated into persistent detection or recurrence-reduction effects.
- Dedicated Knowledge Base UI.
- Relevant internal knowledge surfaced directly in live incident workstations.
- Browser/mobile and Scriptable integration.

## Design principle

Knowledge is not a magic hint. Every lesson keeps provenance: where it came from, which models were involved, which engineers contributed, what evidence supported it, and how strongly it has been reinforced.

## Future extensions

- Hardware/software-context fingerprints so staleness is based on actual environment changes rather than age alone.
- Automatic contradiction detection between experiment findings.
- Interactive superseding flow when newer evidence reverses an old lesson.
- NPC-specific retrieval based on personal memory versus company-wide access.
- Stronger recurrence simulation where preventive standards change incident generation probabilities.
- Launch checklists generated from institutionalized standards.

The next planned Phase 4B.3 slice is employee growth: domain experience, mentoring, promotion readiness, workload consequences, autonomy, and career events.
