## Behavior and ownership

`frontier-mail-frontieros.js` uses the existing `fundingMailStatus` Finance reader for both triage eligibility and decision summaries. Pending requests have no reviewer label. Delegated requests resolve their assigned ID against the current committee; a present reviewer without a display name falls back to the ID. Missing assignments, missing employees and removed committee members show an explicit unavailable label. The founder retains final decision authority.

Only Needs decision rows render this context. Inbox, Unread, Starred and Archive keep their existing rows. Archived actionable requests stay archived. Missing owners/requests/initiatives, changed funding sources, closed requests and unsupported request types remain excluded. Low approval cash does not remove an otherwise actionable row.

Names are escaped text and wrap within the row, including long unbroken names. There are no nested approval or delegation controls. Search continues to match the existing conversation fields and historical messages; the new current-reviewer label does not change search semantics. A reassignment, current name change or reviewer removal is reflected on the next Mail render or reload. Historical delegation names and immutable evidence remain unchanged.

The diagnostic snapshot includes a derived `decisionSummary`; persistent Mail records do not. The same owner request remains authoritative when Finance has saved a reassignment but projecting its new history into Mail failed. Exact retry repairs that projection without reapplying the owner mutation. No schema migration, second request ledger, scheduler, notification system or Finance mutation change is introduced. Mail stays v3, committee v2 and release policy v19; PWA cache v56 refreshes the changed JS/CSS.
