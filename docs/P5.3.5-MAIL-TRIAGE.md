## Behavior

- **Needs decision** includes only typed Finance requests whose owner reports `available` and whose saved status is pending or delegated. Missing owners/records/initiatives, changed funding sources, closed requests and unsupported types are excluded.
- Low cash does not hide a request: rejection and delegation can remain actionable even when approval is unavailable.
- Archived requests appear here while staying archived. Ordinary Inbox, Unread, Starred and Archive membership is unchanged.
- Search filters the triage rows; the folder badge counts all actionable requests. Empty and no-search-match states explain the result.
- Approving or rejecting removes the request from the list/count immediately while keeping the selected original thread open. Back to message list shows the remaining work. Historical messages and evidence stay accessible in their normal folders.
- Folder and row clicks use the existing navigation owner. `frontieros://mail/needs-decision` restores the view; `frontieros://mail/thread/<id>/from/needs-decision` restores the original thread and its folder after reload. Existing plain thread routes remain supported. Finance and Artifacts return to the exact thread; reloading another app can reset the Mail folder context to Inbox on return, without changing the thread.
- Mail schema v3, committee schema v2 and storage keys remain unchanged. This is a local simulation projection, not a new ledger, scheduler or authorization system.
