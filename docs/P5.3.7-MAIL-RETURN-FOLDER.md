## Routes and ownership

Mail emits `initiative/<id>/return/<thread>/from/<folder>` for Finance and `finance-evidence/<request>/<record>/return/<thread>/from/<folder>` for Artifacts. Each dynamic segment is encoded. The existing FrontierOS session owner persists these routes through reload; each destination reads the return folder from its route and uses `thread/<thread>/from/<folder>` for Back to request. Mail's existing folder parser remains authoritative.

Finance keeps its clone-safe return control. Artifacts keeps its read-only evidence reader and request/record matching guards. Their diagnostic snapshots expose the parsed `returnFolder`. Older return links still work without a folder suffix, preserving the existing plain-thread behavior and Mail's current/default folder. Opening an unrelated destination resets the prior return context.

Archived requests remain archived. Returning to an approved/rejected request does not reopen the decision or add it back to Needs decision. No ledger, save schema, request ID, funding behavior, notification or new navigation store is introduced. Search text and scroll restoration are outside this slice.
