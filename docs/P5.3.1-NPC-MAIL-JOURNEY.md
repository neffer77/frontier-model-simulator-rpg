# P5.3.1 — NPC advice → Mail → Run Monitor

## Outcome

P5.3.1 turns the existing NPC second-opinion mechanic into the first native, persistent FrontierOS cross-app journey:

1. Open a live incident in Run Monitor.
2. Select an existing employee in **Ask Team**.
3. Generate advice through the canonical NPC/domain mutation.
4. Deliver that advice to one persistent Frontier Mail thread.
5. Open the exact originating run, incident, and Run Monitor view from Mail.
6. Return explicitly to the same advice thread.

The slice does not introduce a second NPC model, mailbox, or incident record. It adapts existing ownership through the command/event boundary.

## Ownership and state boundaries

- `npc-team.js` remains the owner of advice text, confidence, trust, workload, memory, and `incidentsHelped` mutations.
- `postmortems.js` remains the owner of incident participant/timeline history.
- `frontier-mail-command.js` owns orchestration and idempotency, not domain calculation.
- `frontier-mail-frontieros.js` owns Mail schema migration, thread persistence, linked-entity availability, and Mail presentation.
- `run-monitor-frontieros.js` owns the native Ask Team and return controls.
- `frontieros-session.js` remains the navigation/history owner; `desktop-frontieros.js` now preserves its deep-link payload just as the phone shell already did.

The stable request key is scoped to incident record + run identity + employee. A retry first resolves that key and exits without invoking canonical advice again.

## Observability and replay

The journey records command lifecycle events plus:

- `run-monitor.team.requested`
- `run-monitor.team.delivered` / `run-monitor.team.failed`
- `npc.advice.mail.delivered` / `npc.advice.mail.reused`
- `mail.advice.linked`
- `mail.advice.link.opened` / `mail.advice.link.unavailable`

Advice delivery uses a persisted logical Mail clock and stable message ID. `frontierMailReplaySnapshot()` exposes the session-start and current mailbox snapshots, and the debug bundle embeds both alongside serialized replayable commands.

## Release contract

P5.3.1 advances the canonical policy to v15 and adds the blocker gate `frontieros-npc-mail-journey`. Its focused workflow builds the production site, runs the domain contract, drives the real UI at 390×844 and 1440×1000, captures screenshots and Playwright traces, checks page errors, and uploads `artifacts/npc-mail-frontieros`.

The 190-route and 255-screenshot contracts remain unchanged. PWA cache v49 invalidates stale runtime assets. Scriptable keeps the same asset manifest because this slice modifies already-packaged runtime files and adds no new runtime asset.

## Deliberately deferred

- Approve/reject/delegate actions from typed Mail requests.
- Background or delayed NPC responses.
- Attachments and evidence sharing inside Mail.
- Historical Run Monitor playback after an incident is resolved.
- Physical-iPhone sign-off; Playwright phone emulation is automated evidence, not device certification.
