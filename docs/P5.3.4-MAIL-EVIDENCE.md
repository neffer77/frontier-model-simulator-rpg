# P5.3.4 — Immutable Finance evidence in Mail and Artifacts

## Gap and scope

P5.3.3 saved the committee's explanation but had no evidence attachment. The first regression failed with “Missing immutable Finance evidence attachment” on the merged P5.3.3 baseline.

A pending or delegated funding request now offers **Attach evidence**. It captures one Finance record, adds an attachment to that same Mail thread, and opens a read-only **Finance evidence snapshot** view in the existing Artifacts app. **Back to request** returns to the exact thread.

## Ownership and contracts

- `mail.decision.respond` accepts `attach-evidence`, resolving the owner request from the stored thread reference. Caller-supplied content and request IDs cannot replace Finance evidence.
- Finance validates the current request and expected revision. One capture increments the revision and appends an audit receipt while preserving pending/delegated status, delegate, money, portfolio, NPCs, gate state and monetary decision history.
- Snapshot schema v1 records a stable ID, request ID/revision, deterministic capture clock/day, original source fingerprint, request amount/stage/status, initiative financial inputs, gate evidence/spend, effective scenario weights/theme multipliers and canonical scenario EV/option value.
- The snapshot captures evidence **when Attach evidence is selected**. It does not claim to reconstruct the request creation time or a previous follow-up's assumptions.
- An exact retry reuses the original receipt even after later decisions or source deletion. A new capture on the same request is denied. Stale revisions, unavailable initiatives, closed requests and non-finite evidence cannot create a snapshot.
- Simulation persistence failure rolls back the audit. A Mail projection failure leaves the canonical snapshot safe; retry or thread rendering restores missing references/messages without recapturing it.
- `fundingEvidenceSnapshot(requestId,evidenceId)` returns a copy of the saved audit entry. Artifacts reads that copy without initializing the engineering lab, evaluating current metrics or progressing the simulation.
- The route is `frontieros://artifacts/finance-evidence/<requestId>/<evidenceId>/return/<threadId>`. Return context is checked against the original Finance request, including after source removal. Missing owner records are shown as unavailable and never reconstructed from live data.
- Mail schema v3/storage key and committee schema v2 remain compatible through additive fields. The record is immutable through supported app commands; this is not tamper-proof storage, multi-tab transactional concurrency or real multi-user reviewer authentication.

## Validation and release

- `node tests/mail-evidence-domain.mjs`: invariant, stale/revision, duplicate, subsequent decision, owner/Mail save-failure, partial projection recovery, reload, defensive-copy, pure Artifacts read, missing-record and deterministic replay coverage. Writes success/failure reports with per-command hashes.
- `npm run test:mail-evidence`: domain coverage plus five canonical browser viewports. Real UI clicks capture evidence, open Artifacts, return, and approve/reject. Phone and desktop also reload the viewer, remove the live initiative/change assumptions, and verify explicit missing-record handling. Screenshots, traces and event/state evidence are retained on success and failure.
- Existing Mail decision and follow-up regressions remain required. The control layout assertion accounts for the new sixth control without reducing target-size or overflow requirements.
- Policy v18 adds a blocking native gate; PWA cache v52 delivers the updated assets. The route/capture contracts remain 190/255 and Playwright remains pinned to 1.54.2. No baseline changes.
